# UX re-check: NoAIVerdad (2026-10-27)

**Scope:** Resumen (all tabs, focus on "Red de pagadores"), Provincias, Comparar and Método at desktop (1623×846) and phone (375×812), dark theme. Console checked for errors.
**Not covered:** light theme after the v7 changes, 768 px tablet width, a screen-reader run, keyboard-only walk of the whole site (only the graph's nodes were made focusable), 200 % zoom.
**Environment:** frontend `:3000`, backend `:8000`, Meta token configured (value never read). Login bypass `?debug=1` used.

## 1. Summary
The data and wording are credible; the problem was layout. On the Red tab the graph, the whole point of the tab, started at y = 829 on an 846 px screen, behind two rows of KPI cards, a long intro and about 12 controls, with its details panel below it. The graph itself used a fixed 760×460 box, spread small clusters across it and showed an amount label on every line.
Top issues: (1) graph below the fold, (2) too many controls before content, (3) detail panel far from the graph, (4) edge-label clutter, (5) the same KPI cards repeated on every Resumen tab.
Single change that helps most: put the one thing the user came for first and keep everything else one click away.

## 4. What already works well
Ranges are shown as ranges, estimates are labeled, "indicator, not proof" wording, empty and error states with a retry, deep links per view, source and date line on Resumen, bottom nav on phones.
